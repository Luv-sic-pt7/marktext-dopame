# 演示脚本与真实 Agent 验收

建议演示约四分钟，先人工编辑，再展示两个获授权会话接力，最后说明提交恢复和验收边界。角色 A/B 表示产品使用者，和四名开发成员分工分别记录。

1. 启动最终包，导入带中文、emoji、列表和围栏代码的 Markdown。指出标题下的“保存到私有笔记”，编辑、保存并显式导出。原文件保持原样。
2. 管理员配对 writer/reviewer 两个身份。writer 可以创建文档并管理自己的文档；reviewer 对指定报告只有 read/propose，按需要允许返回建议读取权。展示授权范围，不展示凭证内容。
3. 写作会话通过工具目录创建报告并查询 taskId 至完成，将固定文档引用和有限授权交给 reviewer。审阅会话读取该 revision 与大纲，提出建议。普通宿主按 tools/list 发现能力，无需阅读客户端源码。
4. 用户打开差异并确认应用。一次撤销回到应用前，一次重做恢复建议。通过工具按新 revision 保存、导出并读取 ArtifactRef，结果从结构化接口取得。
5. 展示一个旧版本建议应用的 REVISION_CONFLICT，以及撤销后读取固定产物的 PERMISSION_DENIED。关闭编辑器后查询已有任务/产物，说明查询不启动窗口。
6. 说明本机验证、两个真实会话和官方设备各自状态。按实测记录窗口与耗时，不承诺提速比例。

## 会话提示词

写作会话：使用已连接的 MarkText 工具，发现当前身份可用的能力。创建“示例报告”，正文含标题“项目记录”、中文与 emoji、一段列表和代码。为本次创建使用稳定 requestId，查询原 taskId 直到终态，读取大纲并报告 DocumentRef。不能用屏幕或宿主文件读取结果，不能改变授权。

审阅会话：根据发起方给出的 DocumentRef、revision 和完成标准，通过 MarkText 工具读取该固定版本和大纲。提出一个明确理由的建议，保留原文，返回 proposalId 与差异引用。不得直接应用或保存报告。将结果读取权在既有可转授权范围内交还 writer，或等待用户确认。

应用阶段：由用户确认，或由已明确取得 apply/write/save 权限的会话提交 expectedRevision 一致的应用请求。查询终态后保存、导出并读取固定产物，记录版本和摘要。断线重用原 requestId，不能把接受回执当作完成。

## 记录要求

记录实际宿主、模型/会话标识、两份独立身份、工具发现与调用日志、版本、任务和产物引用、权限拒绝、恢复与窗口观察。不得记录 token、管理员/worker 凭证或完整敏感正文。确定性 stdio host 的记录只能作为协议联调，不能把 M3/M4 标为通过。
